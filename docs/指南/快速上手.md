# 快速上手

十分钟内把 Keel 在本机跑起来：起服务、以买家身份下一单、进商家后台上架一件商品。

需要的东西只有 **Docker（带 compose 插件）** 和 `curl`。不需要装 Go、Node 或 PostgreSQL。

---

## 1. 起服务

```bash
git clone https://github.com/jackwangfeng/keel && cd keel
docker compose up -d --build
./scripts/smoke.sh          # 退出码 0 表示整条链路是通的
```

`docker compose up` 会依次起这些东西：

| 服务 | 作用 | 访问方式 |
|---|---|---|
| `postgres` | 唯一的数据库（带 PostGIS 与 pgvector） | 默认不映射到宿主机 |
| `migrate` | 跑一遍数据库迁移，跑完退出 | — |
| `seed` | 播一家演示店铺（商品、类目、优惠券、一个买家），跑完退出 | — |
| `app` | API 服务 | `http://localhost:8080/api/v1` |
| `console` | 商家后台界面 | `http://localhost:8081` |

第一次构建要编 Go 和 Rust（事务协调器 dtmrs），大约几分钟；之后有缓存会快很多。

**端口被占了？** 整组换掉：

```bash
export KEEL_HTTP_PORT=18080 KEEL_CONSOLE_PORT=18081
docker compose up -d --build
./scripts/smoke.sh
```

`smoke.sh` 读的是同一个变量，所以不用改它。

## 2. 以买家身份逛一圈

种子里有一个固定的买家账号：**手机号 `13800000000`，密码 `keel-demo-2026`**。
这是本地演示用的开发种子，不是生产默认密码。

```bash
B=http://localhost:8080/api/v1

# 商品列表 —— 请求里没有任何东西说明「哪家店」：单商家部署，租户就是那一家
curl -s $B/products | head -c 400; echo

# 类目树
curl -s $B/categories | head -c 300; echo

# 搜索（没配推理引擎时走关键词检索；explain 会如实列出这次跑了哪些阶段）
curl -s -X POST $B/search -H 'Content-Type: application/json' \
     -d '{"query":"咖啡","explain":true}' | head -c 400; echo

# 登录，拿到 access_token
TOKEN=$(curl -s $B/auth/login -H 'Content-Type: application/json' \
        -d '{"phone":"13800000000","password":"keel-demo-2026"}' \
        | python3 -c 'import sys,json;print(json.load(sys.stdin)["access_token"])')

# 我能领的券 / 我已有的券
curl -s $B/coupon-templates -H "Authorization: Bearer $TOKEN" | head -c 300; echo
curl -s $B/coupons          -H "Authorization: Bearer $TOKEN" | head -c 300; echo
```

**下单 → 支付**这一段请直接看 [`scripts/smoke.sh`](../../scripts/smoke.sh)：
它就是一份可执行的教程，每一步都打印出它在调哪个接口，依次是
门店解析 → 试算（`/orders/preview`）→ 下单（带 `Idempotency-Key`）→
发起沙箱支付 → 把签好名的回调投回去 → 确认订单变成已支付、库存扣对了。

> 支付是**沙箱**：不走任何真实渠道，但回调走的是和真实渠道完全相同的那条路
> （验签、金额校验、按渠道流水号去重）。部署到线上时必须关掉，见
> [部署与配置](./部署与配置.md#上线前必须改的)。

## 3. 进商家后台

打开 <http://localhost:8081>。第一次进去要一串**引导 token**，
它在启动时生成、明文打进 app 的日志，24 小时有效、用一次就失效：

```bash
docker compose logs app | grep bootstrap_token
```

在登录页「首次进入」那一栏填 token 和你自己的邮箱，就得到一个**平台管理员**会话。
然后可以：

1. **类目** → 建一个类目
2. **商品** → 新建商品 → 传图 → 加 SKU → 设价格和库存 → 上架
3. 回到第 2 步的 `curl $B/products`，新商品已经在列表里了，也搜得到

后台每一页怎么用、各角色能做什么，见 [后台使用手册](./后台使用手册.md)。

> **token 过期了？** 只要还没有人用它登录过，重启 app 就会补签一串新的：
> `docker compose restart app`，再看一次日志。
>
> **还在有效期内但弄丢了？** 重启**不会**补签——有效期内每重启一次就多一把
> 后台全权的钥匙，这是刻意的。处理办法见
> [常见问题](./常见问题.md#引导-token-弄丢了)。

## 5. 语义搜索（可选，需要 NVIDIA GPU）

不配推理引擎，搜索照样能用，只是只有关键词那一路。
要打开语义检索，先在宿主机上起 [infero](https://github.com/jackwangfeng/infero)，再叠加一个 compose 文件：

```bash
./scripts/infero-up.sh
docker compose -f compose.yaml -f compose.infero.yaml up -d
```

为什么推理引擎不放进 compose，见 README 里「还没在盒子里的」那一节。

---

## 6. 收拾

```bash
docker compose down        # 停掉，数据保留在具名卷里
docker compose down -v     # 连数据一起删（种子会在下次 up 时重新播）
```
