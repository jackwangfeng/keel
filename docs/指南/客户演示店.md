# 客户演示店：按客户的商品清单开一家「像他自己店」的店

见客户之前用这个。拿到他的商品清单，十分钟内得到一家用他自己商品的店，
带两周的模拟经营数据。这样 AI 员工的提案和复盘讲的都是他的货：

- **卖得快、快断货的**（补货 / 渠道分配提案）
- **压着不动的**（滞销清仓提案。每日巡店不跑这一项，要另外让 AI 员工按 `agent/skills/滞销清仓.md` 做一次）
- **顾客搜了店里没有的**（搜索缺口，要推理引擎，见下）

跑完会打印一页「能讲的数字」，例如：

```
==== 鑫惠超市（xinhui）演示店：能讲的数字 ====
在售商品 33 件；近 14 天 226 单、成交 ¥17429.80，客单价 ¥77.12
快卖断的货（可售不到 3 天）11 个：赣南脐橙 2.5kg装 剩 1、矿泉水 剩 1、海南香蕉 剩 2 …
压着不动的货（14 天卖 ≤1 件、库存 ≥20）4 个：陈醋 压 79、保鲜袋 压 70 …
```

实测（2026-10-16，示例清单，14 天）：建店约 2 分钟。AI 员工巡一次店出了 10 条补货提案
（薯片、矿泉水、脐橙、可乐、抽纸、香蕉、鲜牛奶……按卖断先后排）和一份巡店日报，等店长在后台批准。

**这些都是模拟数据**，给客户看的时候要说清楚：店和商品是他的，订单是模拟的。

## 准备清单

格式就是后台「批量导入」认的那份模板（xlsx 或 csv，列名见后台「下载模板」），
可以照 [`deploy/prospect/示例-社区超市.csv`](../../deploy/prospect/示例-社区超市.csv) 填。

- **类目**一列写 `生鲜>水果` 这样的路径，脚本会先把类目树建好。留空的话，
  有推理引擎时按标题推荐，没有就归到「未分类」。
- **可以多加一列「演示热度」**（填 热 / 平 / 冷），用来决定模拟经营里哪些货好卖、哪些滞销。
  导入会把这一列当作不认识的列忽略。没有这一列（或者是 xlsx）时，按 `--seed` 随机分档。
- 没有商品图时，脚本给每件商品画一张写着商品名的浅色「示意图」。有真图的话，导入后到后台商品页上传。

## 跑

```bash
make multi-up                      # 多商家栈（keelmulti），已在跑可跳过
make multi-verify                  # 第一次要跑：它缓存平台会话，开店要用
make prospect-demo CATALOG=鑫惠超市.xlsx CODE=xinhui NAME=鑫惠超市 [DAYS=14]
```

`CODE` 是店铺编码，用小写字母、数字和连字符。脚本会给店登记域名 `xinhui.127.0.0.1.nip.io`
（nip.io 是公共 DNS，泛解析到 127.0.0.1），本机浏览器和 AI 员工都通过这个域名进店。
最后打印一次性的后台登录 token（只显示这一次），AI 员工密钥存在 `~/.config/keel/prospect-<code>-agent-key`。

之后的操作：

```bash
python3 scripts/prospect-demo.py run-agent --code xinhui   # AI 员工巡一次店（会真调 Claude，按一次巡店计费）
python3 scripts/prospect-demo.py simulate  --code xinhui --orders 5   # 当场再下几单，让数字动起来
python3 scripts/prospect-demo.py report    --code xinhui   # 再打印一次那页数字
```

换栈时加 `--project <compose 项目名>`，端口用环境变量 `KEEL_HTTP_PORT` 指定，其他参数见 `--help`。

## 要知道的

- **搜索缺口要推理引擎**：商品的检索数据（向量、bigram 串）由异步索引任务写，
  而这个任务只在配了 `KEEL_EMBED_ENDPOINT` 时才启动。多商家栈默认没配，这时新店搜不到任何商品。
  脚本检测到这种情况就**不模拟搜索**，报告里会写明原因，避免出一个「全搜不到」的假缺口数字。
  要演示这一段，起栈时带上 infero（`scripts/infero-up.sh` 加上 `compose.infero.yaml`）。
- **哪些步骤直接改库**：只有下单和付款走真实接口（SAGA、沙箱支付）。以下几步直接改库：
  建模拟顾客（口令哈希抄种子里的买家 `13800000001`，口令 `keel-dev-2026`）、
  给新店配沙箱支付的回调密钥（种子只给 shop-a / shop-b 配了）、
  把每天的订单挪到过去的日期（接口没有「补历史」这个能力）。所以**只用在演示栈上**，不要对生产栈跑。
- 同一个 `CODE` 只能建一次（编码唯一）。重来就换一个编码，或者 `make multi-wipe` 整栈清掉。
