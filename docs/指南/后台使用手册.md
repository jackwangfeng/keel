# 后台使用手册

商家后台是一个 Vue 3 + Element Plus 的中文界面，`docker compose up` 时一起启动，默认地址
<http://localhost:8081>。它的所有请求和响应类型都从 OpenAPI 契约生成，**界面能做的事情，
用 API 也都能做**，见 [API 接入指南](./API接入指南.md)。

> 界面上按钮置灰只是为了体验。真正的权限由服务端逐条检查：绕过界面直接调接口，
> 该拒绝的照样拒绝（返回 403）。

---

## 登录

后台**没有密码**，一共三种进入方式：

| 方式 | 谁用 | token 从哪儿来 | 有效期 |
|---|---|---|---|
| **首次进入（引导 token）** | 部署后的第一个人 | 应用启动日志：`docker compose logs app \| grep bootstrap_token` | 24 小时，用一次就失效 |
| **已有登录 token** | 管理员新加的员工 | 管理员新建员工时生成，同时打进应用日志：`docker compose logs app \| grep 登录链接` | 15 分钟，用一次就失效 |
| 申请邮件链接 | — | **这个版本没有实现**：项目还没接邮件服务，服务端会回 501 | — |

登录之后得到一个**会话**，7 天有效。右上角可以「复制会话 token」，拿去调 API 时用。

> **为什么引导 token 打在日志里、而不是发邮件？** 全新部署时邮件服务大概率还没配。
> 如果邮件是唯一入口，第一次就进不去后台，而本项目承诺的是「一条命令起来就能用」。
> 代价是日志里会短暂出现一个高权限凭据，所以它用一次就失效。

## 平台级与商家级

后台的账号分两层：

- **平台级**：部署的运营方。第一个通过引导 token 进来的人就是平台管理员。
  平台级账号能开店、停用商家，还能**切换当前管理哪一家店**（顶栏的商家切换器）。
  切换之后，所有页面操作的都是选中的那家店。
- **商家级**：某一家店自己的员工，只能看到、操作自己这家店，没有商家切换器。

单商家部署下只有一家店，平台级账号直接管理它。

## 角色与权限

员工的角色有四种。后两种只存在于商家级，并且要指定**管辖范围**（管哪些大区、哪些门店，一个人可以管多个）：

| 能做什么 | 管理员 | 操作员 | 大区管理员 | 门店管理员 |
|---|:-:|:-:|:-:|:-:|
| 商品、SKU、基准价、类目、上传 | ✅ | ✅ | 只读 | 只读 |
| 大区：改、删、大区价、大区上下架 | ✅ | ✅ | 只限自己的大区 | ❌ |
| 大区：新建 | ✅ | ✅ | ❌ | ❌ |
| 门店：建、改、删、画围栏 | ✅ | ✅ | 只限本大区的门店 | ❌ |
| 门店价、门店上下架、门店库存 | ✅ | ✅ | 本大区的门店 | 只限自己的门店 |
| 设默认门店 | ✅ | ❌ | ❌ | ❌ |
| 店铺设置（时区、自动确认收货天数、退货寄回时限、客服电话） | ✅ | ❌ | ❌ | ❌ |
| 优惠券 | ✅ | ✅ | ❌ | ❌ |
| 营销活动 | ✅ | ✅ | ❌ | ❌ |
| 运费模板：全店模板（建、改、删、设默认）；商品挂哪个模板 | ✅ | ✅ | 只读 | 只读 |
| 运费模板：门店模板 | ✅ | ✅ | 本大区的门店 | 只限自己的门店 |
| 员工管理 | ✅ | ❌ | 只能加、改本大区门店的门店管理员 | ❌ |
| 经营概览（指标、趋势、排行、门店对比、库存预警，含导出） | ✅ | ✅ | 本大区的门店 | 只限自己的门店 |
| 经营概览里的搜索概况 | ✅ | ✅ | ❌ | ❌ |
| 开店、停用商家 | 仅平台级管理员 | | | |

- 列表类页面对大区管理员、门店管理员只显示管辖范围内的东西；商品目录全员可读。
- 被拒绝时服务端返回 403，界面会说明是「角色不允许」还是「超出管辖范围」。
- 每家店至少要保留一个在岗管理员：把最后一个管理员降级或停用会被拒绝。

## 经营概览

登录之后的首页。左侧菜单第一项也是它。一页看完：**指标卡与环比、销售趋势、商品排行、
门店 / 大区对比、库存预警、搜索概况**。全部是固定口径的报表，不用 AI，每次打开现场计算
（没有「数据几点更新」一说，看到的就是此刻的数）。

### 时间与筛选

- 顶部选时间：**今日**（今天 0 点到此刻）、**昨日**、**近 7 天**、**近 30 天**（都是**完整**的
  自然日，**不含今天** —— 今天还没过完，放进去会让每天早上的数字都偏低）、**自定义**（起止两天都含，
  **最多 366 天**）。
- 「今天」「按天」「按小时」全部按**店铺时区**切（**店铺设置**页里改），没改过按
  **Asia/Shanghai**。改完之后下一次打开报表就按新时区算。页面顶部那行灰字会写出本次统计的起止日期和实际用的时区。
- 环比对的是**紧挨着的上一段、等长**：今日对比**昨日同一时段**（昨天 0 点到昨天的此刻），
  昨日对比前日，近 7 天对比再往前的 7 天，自定义同理。
- 可以选一家门店只看它；**门店对比**与**搜索概况**不跟着门店筛选走（前者本来就按门店展开，
  后者没有门店这一维）。
- 金额一律按「分」计算、按元显示，没有任何四舍五入以外的换算。

### 每个指标的口径

先记住两条归属规则，所有数字都照它算：

- **销售按支付时间算**：一单在哪天付的款，就算哪天的销售。下单了没付钱不是销售；
  23:50 下单、第二天 00:10 付款，算第二天。
- **退款按到账时间算**：退款单变成「已退款」（钱真的退出去）的那一刻算。申请了、审核中、
  退款中的都还不算；驳回、撤回的永远不算。**不论那一单哪天付的款** —— 9 月 30 日付款、
  10 月 2 日退款，9 月的销售里有它，10 月的退款里有它。

「已支付的订单」指状态为待发货、已发货、已完成、退款中（整单）、已退款的单；
**草稿、待支付、已关闭 / 已取消一律不计**。整单退掉的单（已退款）仍然计入支付 —— 它确实付过钱，
退掉的部分由退款金额扣回。

| 指标 | 口径 |
|---|---|
| 销售额（净） | 支付金额 − 退款金额。可以是负数（这段时间退的比卖的多） |
| 支付金额 | 支付时间落在这段时间里的已支付订单的**实付**之和（含运费、已扣优惠券） |
| 支付订单数 | 上面那些订单的笔数 |
| 支付买家数 | 上面那些订单的下单买家**去重**人数 |
| 客单价 | 支付金额 ÷ 支付买家数，四舍五入到分；没有买家时为 0 |
| 退款金额 | 到账时间落在这段时间里的退款之和 |
| 退款率 | 退款金额 ÷ 支付金额（同一段时间）。没有支付时显示「—」。因为两边各按各的时间算，**可以超过 100%**（本期退的是上期卖的）。环比按**百分点**写 |

每张卡片右上角的问号里也写着这一句口径。

### 各块报表

- **销售趋势**：支付金额与退款金额两条线，口径同上。只看一天（今日、昨日、自定义选同一天）时
  **按小时**，否则**按天**；没有成交的时段是 0，不会缺一截。今日只画到当前这一小时。
  把鼠标移上去能看到那一格的支付、退款、净销售额和订单数。
- **商品排行 Top 10**：这段时间**付了款**的订单里，各商品的销量与销售额，可以切「按销售额 / 按销量」，
  可以选类目（**含子类目**）。销售额是订单行的实付分摊（行金额减去分摊到这一行的优惠券，**不含运费**）；
  销量是件数，不减退货。旁边的「已退」是**这些订单行截至此刻已经退掉的**件数和金额 ——
  它回答的是「这批销量后来退了多少」，不按退款时间切，所以**不要**拿它和上面的退款金额相加减。
- **门店对比**：各门店的净销售额与支付订单数（口径同指标卡），可以切到**按大区**合计。
  没有成交的门店以 0 列出，方便看出哪家店没动静；已删除的门店只在这段时间有成交或退款时出现。
  大区取门店**现在**所属的大区。
- **库存预警**：**此刻**可售库存不高于预警线（门店库存里设的「预警线」）的门店 SKU，最缺的在最前面。
  预警线是 0 的 SKU 卖空了也会列出来 —— 卖空是最该补货的一种。不含已删除的门店和商品。这一块不看时间。
- **搜索概况**（只有管理员、操作员看得到）：这段时间买家搜索的次数、**无结果率**（搜了但一件商品都没返回的
  比例）、有点击的搜索次数、**热门搜索词**和**无结果搜索词**。搜索词去掉首尾空格、不分大小写合并。
  **无结果搜索词最值得看**：买家在找、店里没有，是最直接的选品信号。

### 导出

**商品排行**与**门店对比**两张卡片右上角各有一个「**导出**」，下载一个 CSV 文件，导出的就是你眼前那张表
（同样的时间、门店筛选、类目、排序、Top 10）。文件名带着起止日期。

- 用 Excel 双击就能打开，中文不会乱码（文件是 UTF-8 带 BOM）；金额按**元**写、两位小数，可以直接求和。
- 门店对比先列门店、再列大区小计，第一列「类型」区分。
- 商品标题以 `=`、`+`、`-`、`@` 开头的，导出时前面会多一个单引号 `'` —— 防止 Excel 把它当成公式执行。
- 谁能导出、导出的范围，和看这张表完全一样（门店管理员导出的只有自己门店的数）。

### 谁能看什么

和订单同一个口径：管理员、操作员看全店；大区管理员只算本大区门店的单；门店管理员只算自己门店的单
（按订单的履约门店，门店的大区取它现在所属的大区）。库存预警同理。
**搜索概况只有管理员、操作员能看**：搜索日志上没有门店这一维，没法只给门店管理员看他那一份。
选一家不归你管的门店，得到的是全零，而不是报错。

### 为什么自定义最多 366 天

每次打开都是对这段时间的明细现场计算（没有预先汇总的表），时间越长算得越久。
366 天覆盖「今年以来」「和去年比」这两种最长的日常问法；更长的分析应该导出到数据仓库去做，
而不是压在处理订单的数据库上。

背后的接口：

| 报表 | 接口 |
|---|---|
| 指标卡与环比 | `GET /admin/reports/overview` |
| 销售趋势 | `GET /admin/reports/trend` |
| 商品排行 | `GET /admin/reports/products` |
| 门店 / 大区对比 | `GET /admin/reports/stores` |
| 导出商品排行 / 门店对比 | `GET /admin/reports/products.csv`、`GET /admin/reports/stores.csv` |
| 库存预警 | `GET /admin/reports/inventory-alerts` |
| 搜索概况 | `GET /admin/reports/search` |

## 商品

**商品 → 新建**，然后在商品详情页依次完成：

1. **基本信息**：标题、副标题、类目、描述，以及**运费模板**（可选，见[运费模板](#运费模板)）。
2. **图片**：上传后挂到商品上，可以排序。
3. **SKU**：每个规格一个 SKU，填**基准价**（单位是元，界面会换算成分存储）。
4. **库存**：按门店设置。店铺只有一家门店时，SKU 上可以直接改库存。
   改库存的对话框有两种改法：
   - **加减**（默认）：进货填正数、盘亏填负数，可以写一句原因（最多 200 字）。它加在**当前真实值**上，
     和同时发生的下单扣减互不覆盖；扣完会变负时会拒绝，并告诉你现在还剩几件。
     网络不好时重复点提交也只算一次。每一次加减都会记进库存流水（谁、加减多少、前后各是多少、原因）。
   - **设为**：盘点得出「现在就是 N 件」时用，也是改**预警线**的地方。要填「我看到的值」，
     库存在你打开之后被下单扣过的话会提示你用新值重试。
5. **上架**：上架之后买家才能在列表、搜索里看到它。

发布前会自动做**合规检查**，拦截广告法违禁词（比如「最佳」「全网第一」「国家级」「独一无二」这类绝对化用语），
并告诉你是哪个词、为什么。

> 删除 SKU 是软删除：卖过的 SKU 被历史订单引用着，物理删除做不到，也不应该做。

### 批量导入

**商品 → 批量导入**（列表右上角），一次最多 2000 行、文件不超过 5 MB。

1. **下载模板**：Excel 或 CSV 都行。Excel 模板有两张表：「商品」（只有表头，数据区已经
   设成文本格式）和「填写说明」（每一列怎么填、示例）。
2. **填表**：一行一个 SKU。**同一个商品标题的多行会合并成同一件商品**——比如一件连衣裙有
   红 M、红 L、蓝 M 三个规格，就写三行，标题相同，规格名都写「颜色;尺码」，规格值分别写
   「红;M」「红;L」「蓝;M」。副标题、类目、描述只在这件商品的第一行填就行。
   - 必填：商品标题、SKU 编码、基准价（元，最多两位小数，不要千分位逗号）、库存（写进默认门店）。
   - 类目可以写名字（「连衣裙」）或从一级写到末级（「服装 > 女装 > 连衣裙」）；**留空也行**，
     系统会按标题推荐。
   - 图片 URL 本期**只记录、不下载**，导入后请在商品详情页上传图片。
3. **上传并预检**：预检**不会写入任何东西**，可以反复传。结果表里：
   - **红色行**有错误（必填没填、价格格式不对、SKU 编码重复或店里已经有了、规格对不上……），
     「问题」列写着哪一列、为什么。**一行有错，整件商品都不会导入**（避免只导进去一半规格）。
   - **黄色行**是提示：违禁词（原文上标红）、Excel 把编码存成了数字、合并单元格已按每行填充等。
     违禁词不影响导入——导入的都是草稿，**上架时**才会拦截，请在上架前改掉。
   - **类目**：「按名称匹配」表示你填的类目对上了；「AI 推荐（已选）」表示系统按标题语义推荐、
     而且把握足够，已经替你选好；「需人工确认」表示有候选但把握不够，请从下拉里挑一个
     （候选后面的数字是相似度）；「需手选」表示没有推荐（推理引擎没开或暂时不可用）。
     所有类目在确认前都可以改。
4. **确认导入**：只导入没有错误、而且选了类目的商品。导入的商品**一律是草稿**，不会自动上架。
   结果页列出建成的商品（可以点进去补图、检查后上架）、没导入的商品及原因、文件里填过的图片地址。

几个常见问题：

- **同一份文件点了两次「确认导入」** 不会建出两份：系统认得这份文件，第二次直接给出第一次的结果。
- **改了几行再导一次**：已经建过的商品会因为「SKU 编码在店里已经存在」被跳过，只补上没导进去的。
- **Excel 的坑**：不要用公式（请「复制 → 粘贴为数值」）；表头行不要合并单元格；
  SKU 编码列保持文本格式，否则 Excel 会吃掉前导 0、把「1-2」变成日期（系统会报出来，但救不回原值）。
- **CSV 乱码**：用 Excel「另存为 → CSV UTF-8」最稳；普通的「CSV」（GBK 编码）系统也认得。
- 批量导入和新建商品同一个权限：管理员、操作员可以；大区管理员、门店管理员不行。

**类目**页维护一棵类目树。买家端按类目浏览时，选中一个类目会**包含它的所有子类目**。
优惠券按类目限定范围时也一样。

## 大区与门店

连锁经营用这两个概念：

- **门店**：一个实体服务点，有自己的**电子围栏**（地图上画的一个多边形）和**库存**。
- **大区**：门店的分组，决定这一片**卖什么**、**卖什么价**。

### 价格与可见性：三层覆盖

买家看到的价格和商品，按这个顺序决定：

```
SKU 基准价  →  大区价（覆盖基准价）  →  门店价（覆盖大区价）
商品上架    →  大区上下架             →  门店上下架
```

没有单独设置的层级就沿用上一层。所以一个全国统一价的商家，只设基准价就够了。

### 电子围栏

在门店详情页的地图（OpenStreetMap）上画多边形。买家端带着定位来时，
服务端判断他落在哪家门店的围栏里；不在任何围栏里就回落到**默认门店**。

- 坐标系是 **WGS-84**（GPS 原始坐标），和数据库、买家端定位是同一个坐标系，不做任何换算。
- 也可以粘贴 GeoJSON 或坐标文本导入。**高德、腾讯地图用的是 GCJ-02，百度用的是 BD-09**，
  导入时声明来源坐标系，界面会换算回 WGS-84，并告诉你挪了多少米。
- 至少要有一家**默认门店**，否则没有定位的买家会找不到店。顶栏会提醒你去设。

## 优惠券

**优惠券 → 新建券模板**。

**券型**

| 券型 | 规则 |
|---|---|
| 满减 | 满多少元减多少元 |
| 折扣 | 打几折，可以设封顶（最多减多少元） |
| 立减 | 无门槛直接减 |
| 包邮 | 抵运费：可以设门槛，「封顶」是最多抵多少运费（留空即运费全免），运费最多抵到 0 |

包邮券在**这一单运费为 0**（已经满额包邮，或者店里没配运费模板）时买家用不了 ——
用掉一张一分钱没抵的券比不让用更糟。运费怎么来的见下面[运费模板](#运费模板)。

**其他设置**

- **有效期**：固定起止时间，或者「领取后 N 天内有效」。
- **总量**、**每人限领**。
- **可领取**：打开后券会出现在买家端的**领券中心**，买家自己领。
- **适用范围**：全场、指定类目（含子类目）、指定商品、指定大区、指定门店。
  每条规则可以是「包含」或「排除」，**排除优先**。

**发券的两种方式**

1. **领券中心**：模板设为可领取，买家自己领。领取时防超发，总量卡得住。
2. **定向发放**：在券列表点「定向发券」，按买家 ID 或手机号发给指定的人。

**券发出去之后**，券面（券型、门槛、减免、折扣、封顶）、有效期和适用范围都不能再改：
已经在买家手里的券，规则不应该被改掉。可以停用模板，停用后不能再领、不能再发。

**券在订单里怎么走**：下单时锁定，支付成功后核销；订单超时未支付被关闭时，券自动退回买家。

**券与营销活动一起用时**，券的门槛看的是**活动之后的金额**：一单 100 元先被满减活动减了 10 元，
一张「满 100 减 20」的券就不够门槛了。活动可以设成「不与券同享」，命中它的订单不能再用券。

## 营销活动

**营销活动 → 新建活动**。新建的活动是**下线**的，配完规则、核对无误后在列表里点「上线」。

**五种活动**

| 类型 | 怎么配 | 效果 |
|---|---|---|
| 满减 | 门槛按金额或件数，一到十档（如满 199 减 20、满 399 减 50） | 命中门槛不超过的最高一档，优惠按金额比例分摊到每件商品 |
| 满折 | 同上，每档一个折扣（如满 2 件 9 折、满 3 件 8.5 折） | 同上 |
| 限时折扣 | 选商品的 SKU，每个 SKU 给特价（元）或折扣（折），可设每人限购 | 活动期间按活动价卖 |
| 秒杀 | 同限时折扣，另外必须给**秒杀配额**（按秒杀价最多卖几件） | 配额抢光之后按门店价卖 |
| 新人礼 | 选一批启用中的券 | 还没下过单的买家登录后自动收到一张（一人一张） |

**计价顺序**（固定，改不了）：门店价 → 限时折扣 / 秒杀改单价 → 满减满折 → 优惠券 → 运费。

几条要知道的规则：

- **活动价 = 门店价与特价里低的那个。** 某家门店单独把价调得比特价还低时，那家店按门店价卖，
  活动在那里不生效 —— 特价不会让买家比平时多付钱。
- **一件商品至多参与一个满减满折。** 两个满减范围重叠（全场满 200 减 30、服装满 100 减 20），
  同一件衣服不会被减两次：系统先挑减得多的那个，它占走范围内的商品，剩下的商品再看别的活动。
  范围不重叠的活动各减各的。
- **满减满折的门槛按活动价算**：一件 120 元的商品限时特价 90 元，不能拿 120 元去凑满 100 的门槛。
- **与券同享**：默认同享。关掉之后，命中这个活动的订单不能再用优惠券（买家会看到原因）。
- **每人限购**只算没关闭的订单：订单取消或超时关闭，限购额度自动还回来；退款不还。
- **秒杀配额不是另一份库存。** 每卖出一件，门店库存照样减一件；配额只管「按秒杀价最多卖几件」。
  门店库存不够时照样买不到。
- **适用范围**与优惠券同一套：全场、类目（含子类目）、商品、品牌、大区、门店，排除优先。
  限时折扣 / 秒杀的商品已经由 SKU 点名，范围只能按大区、门店限定（比如秒杀只在北京门店）。

**上线之后**：只能改名、下线。要改规则（阶梯、商品、价格、时间、范围）先下线，改完再上线 ——
上线中的活动随时可能正被买家的试算或下单用着，边用边改会让两边算出不同的钱。
已经下了的订单不受任何修改影响：订单上记着下单那一刻命中的活动与每件商品分到的优惠。

秒杀 / 限时折扣里**已经卖出过的 SKU 不能移出活动**，配额也不能改到低于已售件数。

**阶段**：列表上的「阶段」是现算的 —— 已下线 / 未开始 / 进行中 / 已结束。已结束的活动不会再命中任何
订单，不需要手动下线。

**新人礼**的「新人」指**还没成功下过单**的买家（下单失败、超时未付的不算），在他们登录时发放。
券从你选的那批券里出，占那批券的总量；那批券停用或发完就不再发。

## 运费模板

**运费模板 → 新建模板**。一个模板 = 计费方式 + 按省分组的计费规则 + 包邮条件 + 不配送地区。

**计费方式**

| 方式 | 首件 / 续件的单位 | 按什么算 |
|---|---|---|
| 按件 | 件 | 一单里用这个模板的商品一共几件 |
| 按重量 | 克 | 各 SKU 的**重量**（商品详情 → 规格里填）× 件数；没填重量的按 0 克，只收首重费 |

运费 = 首件（首重）费 + 每超出一个续件（续重）单位加一次续费，不足一个单位按一个算。
例：首件 8 元、每续 1 件 2 元，3 件就是 8 + 2 × 2 = 12 元。

**计费规则按省分组**

- 每条规则选一组省（按省多选；别的规则或「不配送」里已经选了的省会置灰）。
- **必须有且只有一条「其余地区」的默认规则**（不选任何省），没被别的规则选中的省都按它算。
- 典型配法：默认规则「首件 8 元续件 2 元、满 99 包邮」，再加一条「新疆、西藏、青海……首件 15 元续件 5 元、
  不填包邮」—— 这就是「偏远地区另价、不包邮」。

**包邮条件**（挂在每条规则上，满足任一即这一单免运费）

- **满额包邮**：比的是**优惠后**的应付商品金额 —— 营销活动、优惠券都减完之后。
  所以「满 99 包邮」遇上「满 100 减 20」的券，100 元的货用券之后是 80 元，**不包邮**。
- **满件包邮**：整单件数达到就包邮。

**不配送地区**：收货地址在这些省时，买家下单会被拒，并逐行告诉他哪几件送不到。

**一件商品用哪个模板**（按顺序，先命中先用）：

1. 商品详情里**单独挂**的模板（只能挂全店模板）；
2. 发货门店的**门店模板**（每家门店至多一个）；
3. **全店默认模板**（模板上打开「全店默认」，同一时刻只有一个）；
4. 都没有：这件商品不计运费。

一单里的商品用了不同模板时，各自算、加起来。

**改模板只影响之后的订单**：订单上记着下单那一刻用的是哪条规则（订单详情的运费明细），
改模板、删模板都不会改历史订单。还有商品挂着的模板删不掉，要先在商品详情里改挂别的。

**售后退运费**：未发货整单退款会把运费一起退；退货退款在审核时可以填退运费。
两种情况的上限都是这一单**实收**的运费 —— 用了包邮券的，被券抵掉的那部分买家没付过，不能退。

## 店铺设置

左侧菜单 **店铺设置**（只有管理员看得到；平台级管理员切到某家店之后也能改那家店的）：

| 项 | 说明 |
|---|---|
| 店铺名称 | 只读。改名由平台在「商家管理」里做 |
| 客服电话 | 展示用，留空即不设 |
| 店铺时区 | 经营报表按它切「今天」「按天」。可以从列表里选，也可以输入任意 IANA 时区名（如 `Asia/Tokyo`），服务端会逐个校验，`Local`、缩写（`CST`）不收 |
| 自动确认收货 | 发货后多少天系统替买家确认收货，1～365，默认 7 |
| 退货寄回时限 | 退货退款同意后多少天买家还没填寄回物流就自动关闭，1～365，默认 7 |

保存是整张表一起保存。改完立即生效，没有缓存：报表下一次打开就用新时区，
两个定时任务下一轮（至多十分钟）就按新天数判断 —— 改的是「此刻」的规则，已经发货、已经同意退货的单
也按新天数算。

背后的接口：`GET /admin/shop-settings`、`PUT /admin/shop-settings`。

## 员工

**员工 → 新建**：填邮箱、选角色（大区管理员、门店管理员还要选管辖范围）。

新建成功后，界面和应用日志里都会出现一串**一次性登录 token**（15 分钟有效）。
把它交给对方，对方在登录页「已有登录 token」一栏填入即可进入。

员工的会话 7 天过期，一次性 token 15 分钟过期。过期之后在员工列表点「**重签登录 token**」，
把新 token 交给对方即可，不用删掉重建。重签会作废此人之前没用掉的 token；谁能改这个员工，
谁就能给他重签；停用的员工不能重签。

可以修改角色、管辖范围，或者停用员工。改动在对方的下一个请求就生效：角色和状态不写进会话令牌，每次请求都从库里现查。

## 订单与售后

左侧菜单有两页：**订单**与**售后**。

### 订单页：找单、看单、发货

- 打开时默认筛「已支付 · 待发货」，这就是每天要发的那一堆；把状态清掉就是全部订单。
- 还可以按**门店**、**下单日期**、**单号**、**手机号**找。单号与手机号是**精确匹配**，
  手机号收货人的与下单买家账号的都认（打电话来的人报的号码不一定是收货人那一个）。
  日期按本地日历、两端都含。
- 列表上「售后中」的标签表示这一单有还没处理完的退款单。
- 点一行打开详情：收货人与门店（下单时的快照，门店后来改名不影响）、每一行的单价、
  优惠分摊、已退 / 在途 / 还可退件数，支付记录、发货包裹、这一单的全部退款单
  （点退款单号跳到售后页）。
- **发货**：已支付的单在列表和详情里都有「发货」按钮。选物流公司（顺丰、京东、圆通……
  也可以手填代码），填运单号，确认。一单只发一次，发出后变成「已发货」；不扣库存
  （下单时已经扣过）。同一个物流公司的同一个运单号只能登记一次，录重了会被拒。
  - 有进行中的**部分退款**时仍然可以发货，页面会提醒先看一眼退款单。
  - 买家申请了**整单退款**的单（状态「退款中（整单）」）不能发货，先到售后页处理那张退款单：
    驳回之后订单回到「已支付」，才能发。
- **自动确认收货**：发货后买家一直不点「确认收货」，满 **7 天**系统替他确认，订单变成「已完成」。
  天数在**店铺设置**里改（1～365，默认 7），按「此刻」的天数判断：改短之后，已发货超过新天数的单
  会在十分钟内被确认。买家在订单详情里看得到自动确认的截止时间。这一单有**没处理完的退款单**（待审核 / 待买家退货 / 退款中）时暂停自动确认 ——
  买家正在退货，系统不替他说「货没问题」；退款单结束后，下一轮（至多十分钟）就会确认。

### 售后页：审核与确认收到退货

- 打开时默认筛「待审核」；「待买家退货」在状态下拉里切。也可以按门店、申请日期筛。
- 点一行打开详情：退了哪几件、每一行退多少钱（服务端算好的，**不能改**）、
  货款 + 运费 = 实退合计，所属订单的实付与运费，买家的原因、说明与凭证图片，退货退款的
  **寄回物流**（买家填的物流公司、运单号与填写时间），以及审核记录
  （谁在什么时候同意 / 驳回、驳回理由、买家什么时候填了寄回物流、谁确认收到了退货、渠道到账流水）。
- **凭证图片只有能处理这张退款单的人看得到**：凭证是买家的隐私，买家自己和能打开这张退款单的
  员工（同下面「谁能做」的范围）才读得到；图片地址转发给别人打不开，限时地址 5 分钟就失效。
- **待审核**的单可以：
  - **同意**。仅退款：同意后直接退钱。退货退款：同意后进入「待买家退货」，
    这时可以填**退运费**（按元填，例如 `8.50`；留空就是保持申请时的值），
    最多退到订单实收的运费（扣掉别的退款单已经退过的）。
  - **驳回**，必须写理由 —— 买家会看到这段话，写清楚为什么、改什么可以重新申请。
    整单退款被驳回时，订单回到「已支付」，可以继续发货。
- **待买家退货**的单：买家把货寄回后会在他那边填物流公司和运单号，详情里「寄回物流」一栏能看到，
  照着查件；填错了买家可以改，状态仍是「待买家退货」。收到货之后点「确认收到退货」，才会进入退款。
  买家没填单号也可以确认（比如货是当面退回的）；反过来，填了单号不等于货到了，不会自动往下走。
- **买家超时未寄回**：同意退货之后，买家超过**退货寄回时限**（店铺设置，默认 7 天，从你点「同意」的
  时间算）还没填寄回物流，系统把这张售后单关掉（「已取消」），买家会收到一条通知，可以重新申请。
  已经填了物流的不关，不管填了多久。至多晚十分钟。
  退回来的货**不会自动加回库存**（成色未知），验货后到门店库存里用「加减」加回去，原因写上售后单号。

### 谁能做

订单和售后的看与做，权限都和「门店库存」那一行一样：管理员、操作员全店；
大区管理员只看得见、也只能处理本大区门店的单；门店管理员只看得见、也只能处理自己门店的单。
按订单的**履约门店**算，门店调到别的大区之后，它的单跟着交给新大区的人；
门店删掉之后，它名下的单原大区的人仍然能打开处理。
界面上没权限的按钮是灰的，但真正拦的是服务端（直接调接口一样会被拒）。

背后的接口：

| 操作 | 接口 |
|---|---|
| 订单列表 / 详情 | `GET /admin/orders`、`GET /admin/orders/{order_no}` |
| 发货 | `POST /admin/orders/{order_no}/shipments` |
| 退款单列表 / 详情 | `GET /admin/refunds`、`GET /admin/refunds/{refund_no}` |
| 退款审核 | `POST /admin/refunds/{refund_no}/audit` |
| 确认收到退货 | `POST /admin/refunds/{refund_no}/receipt` |
| 看凭证图片 | `GET /admin/uploads/{upload_id}`（302 到限时地址） |

- **退款金额不由人填**：按下单时的优惠分摊逐行算到分，最后一件吃掉余数，所以一行退完正好等于实付。
- **库存**：订单还没发货就退款，库存自动回补；已经发货的，退回来的货成色未知，不自动回补，需要手工调整。
- **券**：一行的货全部退完，这一行用到的券才退回给买家（已过期的不退）。
- **沙箱**：沙箱支付开着时，审核通过后服务端直接模拟渠道完成退款，马上就能看到「已退款」。

> 买家传了图片却没提交申请、或者换头像换下来的旧头像，超过 24 小时没被用上就会被系统清理掉
> （后台传了却没挂到商品上的图也一样）。已经提交的售后凭证不会被清理。

## 待办提醒（顶栏铃铛）

顶栏右上角有一个铃铛，角标是**你自己**还没读的提醒数，大约每 30 秒刷新一次。
点开是最近 20 条提醒的下拉列表（按时间倒序，未读的有标记）；点一条会把它标成已读并跳过去，
下拉底部有「全部已读」。

| 提醒 | 什么时候出现 | 点了跳到 |
|---|---|---|
| 新订单待发货 | 买家付款成功 | 订单页，打开那一单 |
| 新的售后待审核 | 买家申请了退款 / 退货 | 售后页，打开那张退款单 |
| 买家已寄回退货 | 买家填了（或改了）寄回物流 | 售后页，打开那张退款单 |
| 库存预警 / 商品已售罄 | 下单扣库存之后，门店库存**这一次**降到预警线（门店库存里的「预警值」）或以下；扣到 0 时是「已售罄」 | 那家门店的库存页 |

- **看得到哪些**：每条提醒属于一家门店，范围和订单、售后列表一样 —— 管理员、操作员看全店；
  大区管理员看本大区门店的；门店管理员看自己门店的。别的门店的提醒既看不到，也标不了。
- **已读每人一份**：一条「新订单待发货」管这家店的人都能看到，你点开了只算你读了，
  同事那边仍然是未读。「全部已读」也只标你自己范围里的。
- 库存预警只在「跌破」的那一次提醒，已经在线下的库存每卖一件不会再提醒；补货回到线上后再跌下来，会再提醒一次。
  后台自己改库存不产生提醒（改的人正看着那个数）。
- 提醒保留 **90 天**，更早的会被自动清理（订单、退款单本身不受影响）。
- 同一套机制也给买家发站内消息（支付成功、已发货、售后审核结果、退款到账等），买家在 App 的消息中心里看。
  短信、微信订阅消息、邮件**本期都没有接**，只有站内消息；将来怎么接见
  [消息通知外发渠道接入（草案）](./消息通知外发渠道接入.md)。

背后的接口：`GET /admin/notifications`（列表，带未读数）、`GET /admin/notifications/unread-count`、
`POST /admin/notifications/{notification_id}/read`、`POST /admin/notifications/read-all`。
