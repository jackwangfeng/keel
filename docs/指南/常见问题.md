# 常见问题

## 启动与构建

### `docker compose up` 构建很慢，或者卡在下载依赖

第一次构建要编 Go 和 Rust（事务协调器 dtmrs），还要从 GitHub 拉 dtmrs 的源码，在国内网络下可能很慢。

- Go 模块：在宿主机设好 `GOPROXY`（比如 `export GOPROXY=https://goproxy.cn,direct`），compose 会把它透传进构建。
- 访问 GitHub：给 Docker 构建配代理。注意构建容器里的 `127.0.0.1` 是容器自己，代理地址要写宿主机的局域网 IP：

  ```bash
  docker compose build --build-arg HTTPS_PROXY=http://192.168.x.x:7890 \
                       --build-arg HTTP_PROXY=http://192.168.x.x:7890
  docker compose up -d
  ```

构建过一次之后有缓存，再次构建快得多。

### `curl localhost:8080/...` 返回 404，看起来像 Keel 挂了

先确认 8080 是不是被别的服务占着：这时你的请求打到了**那个服务**上。
换端口起 Keel：`KEEL_HTTP_PORT=18080 docker compose up -d`，然后用 18080 访问。

如果返回的是 Keel 自己的 404（`application/problem+json`，`title` 是「接口不存在」），
说明这条接口在契约里有、但还没有实现，见 [API 接入指南 · 实现进度](./API接入指南.md#实现进度)。

### 应用起不来，日志里说「启动自检未通过，拒绝启动」

这是刻意的：配置对不上时宁可不启动，也不带着错误配置接请求。按日志里的提示处理，常见的几种：

- **连库的角色能绕过行级安全**：`PGUSER` 必须是 `keel_app` 这类普通角色，不能用超级用户 `keel`。
- **`KEEL_DEFAULT_MERCHANT` 不存在或已停用**：单商家形态下它必须和种子里那家店的 code 一致（默认 `demo`）。
- **单商家形态下库里有不止一家活跃商家**：要么切到多商家形态，要么停用多余的商家。
- **`KEEL_DTM_DSN` 没配**：事务协调器的存储没有默认值，必须显式配置，见 [部署与配置](./部署与配置.md)。

### 日志里有一条「沙箱支付是开着的」WARN

本地演示时可以忽略。部署给真实客人时必须设 `KEEL_PAYMENT_SANDBOX=off`，
否则买家可以把自己的订单免费推成「已支付」。

## 后台

### 引导 token 弄丢了

分两种情况：

- **已经过期（超过 24 小时）且从没人用它登录过**：`docker compose restart app`，启动时会补签一串新的，再看日志。
- **还在有效期内**：重启不会补签（有效期内每重启一次就多一把后台全权的钥匙）。等它过期，或者手动作废它再重启：

  ```bash
  docker compose exec postgres psql -U keel -d keel -c \
    "UPDATE staff_tokens SET revoked_at = now() WHERE kind = 1 AND used_at IS NULL AND revoked_at IS NULL;"
  docker compose restart app
  docker compose logs app | grep bootstrap_token
  ```

一旦有人用引导 token 登录过，引导通道就永久关闭了，之后的员工由管理员在后台新建。

### 新员工的登录 token 过期了 / 员工会话过期（7 天）之后怎么重新登录？

管理员在后台**员工**页点这个人的「重签登录 token」，把新的一次性 token（15 分钟有效）交给对方，
对方在登录页「已有登录 token」一栏填入即可。重签会作废此人之前没用掉的 token。
谁能改这个员工，谁就能给他重签；停用的员工不能重签。

对应接口是 `POST /admin/staff/{staff_id}/login-token`。邮件登录链接依赖邮件服务，这个版本还没接。

### 上传的商品图片不见了

v0.1.0 自带的 `compose.yaml` 漏配了 `KEEL_UPLOAD_ROOT`，上传文件落在容器的临时目录里，
容器一重建就没了。新版本已经给上传文件配了单独的持久卷（`uploads`）。
升级之后，**之前丢掉的图片需要重新上传一次**。

### 画的围栏和地图上的位置对不上，偏了几百米

多半是坐标系的问题。Keel 统一用 **WGS-84**（GPS 原始坐标）。
高德、腾讯地图的坐标是 GCJ-02，百度是 BD-09，直接拿来用会偏几百米。
导入围栏时声明来源坐标系，后台会换算回 WGS-84，并告诉你挪了多少米。

## 买家端与搜索

### 重启之后所有买家都要重新登录

没配 `KEEL_AUTH_SECRET`，应用每次启动随机生成一个签名密钥，旧令牌就全部失效了。
配一个固定值即可：`KEEL_AUTH_SECRET=$(openssl rand -base64 48)`，多实例部署要用同一个值。

### 短信验证码登录、微信登录返回 501

这两种登录依赖短信服务和微信开放平台，本项目还没接。501 的意思是「这条路没开」，
不是参数错了。目前可用的是手机号 + 密码登录。

### 搜「夏天穿的显瘦一点的」这种句子搜不到东西

没接推理引擎时，搜索只走关键词检索，和商品标题一个字都不重合的查询召回会很差。
这是设计好的降级，不是故障：请求照样返回 200，`explain: true` 会告诉你这次只跑了关键词那一路。
要打开语义检索，见 [部署与配置 · 语义搜索与推理引擎](./部署与配置.md#语义搜索与推理引擎)。

### `/search` 返回 429

触发了按 IP 的限流（默认每秒 12 次）。放在反向代理后面时，所有请求都算在代理的 IP 上，
很容易触发。见 [部署与配置 · 反向代理](./部署与配置.md#反向代理)。

## 开发

### 怎么跑测试？

见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。简单说：`make test-db` 需要一个 PostgreSQL
（用 `keel-postgres:16` 镜像），`./scripts/check-all.sh` 跑全部闸门。

### 改了接口，要改哪些地方？

先改契约 `docs/电商系统-OpenAPI.yaml`，再 `make generate generate-uts generate-sql`，
最后写实现。生成的产物要一起提交，CI 会检查它们和契约是否一致。
