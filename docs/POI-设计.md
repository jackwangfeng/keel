# POI 与地址（设计草案）

> 2026-09-28 草案，待定：地图服务商的密钥（见 §5）。

## 要解决的三件事

1. **买家端首页**：显示定位到的地址（逆地理编码），不显示门店；用户点地址可以换一个地址（搜索 / 选已有收货地址），
   换了之后按围栏自动换门店。
2. **买家端填收货地址**：搜索地点、地图选点，自动填省市区、街道与坐标，不用整条手打。
3. **后台门店地址**：搜索地点填地址与坐标（现在只有地图选点，地址要手填）。

## 选型（调研结论，2026-09-28）

| 服务商 | POI 搜索 / 输入提示 | 免费额度（个人认证） | 坐标系 | 结论 |
|---|---|---|---|---|
| 高德 Web 服务 | 最好（输入提示体验公认最佳） | POI 与输入提示各 5000 次/月、逆地理编码 15 万次/月，3 QPS；企业认证后 POI 5 万次/月起 | GCJ-02 | **后端代理的主力** |
| 腾讯位置服务 | 好 | 日 1 万次、5 QPS（2025-04 对个人有下调） | GCJ-02 | 小程序选点（`wx.chooseLocation` / 地图选点插件，免 key、不占合法域名）；后端备用源 |
| 百度 | 好 | 地点检索仅 100 次/日；2024-04 起商用不给免费额度、个人不能买商用授权 | BD-09 | 不用 |
| 天地图 | 一般 | 约 1 万次/日（未核实原文） | CGCS2000≈WGS-84 | 不做主力 |

**商用需要企业认证**（高德、百度都明确）。演示站用个人认证的额度够（访客很少）；正式部署由部署方自己申请 key。
调研里有几条没拿到官方原文（高德 2025-05 新定价细则、腾讯 2025-04 下调的具体数值），接入前在控制台核对。

## 架构

- **后端代理，key 不下发**：`GET /api/v1/geo/reverse?lat&lng`、`GET /api/v1/geo/suggest?q&lat&lng&city`、
  `GET /api/v1/geo/search?q&lat&lng`。Web、App、小程序、后台都走它；一把绑服务器 IP 白名单的 Web 服务 key 就够。
- **服务商可换**：`internal/geo` 定义 `Provider` 接口（Reverse / Suggest / Search），实现 `amap`、`tencent`；
  `KEEL_GEO_PROVIDER` + `KEEL_GEO_KEY` 配置；没配时这几条接口回 501，客户端退回现在的手填 + 地图选点（降级，不是故障）。
- **坐标统一 WGS-84**：服务商返回的 GCJ-02 在代理里转成 WGS-84 再给客户端（库里、围栏、门店坐标全是 WGS-84）；
  客户端传来的坐标也按 WGS-84 解释。转换放在一处（Go），有单测对照已知点。
- **缓存与限流**：逆地理编码按坐标取 5 位小数（约 1 米）缓存 1 天；输入提示按 (q, 城市) 缓存 1 小时；
  每个客户端 IP 每分钟 30 次（额度很小，防一个脚本把一天的额度刷完）。
- **返回形状**：`{name, address, province, city, district, adcode, street, lat, lng}` —— 与收货地址的字段对齐，
  `adcode` 就是地址的 `region_code`（运费按它算）。

## 地图底图（2026-09-29）

地图选点、门店坐标、围栏编辑都要一张底图。**底图也走服务端代理**：`GET /api/v1/geo/map` 报配置
（开没开、叠哪几层、最大级别、版权署名），`GET /api/v1/geo/tiles/{layer}/{z}/{x}/{y}` 转发瓦片。

- **天地图**（`KEEL_MAP_TILES=tianditu` + `KEEL_TIANDITU_KEY` + `KEEL_TIANDITU_REFERER`）：国家地理信息公共服务平台，有审图号
  （国内公开展示的地图必须有），免费 key 可商用、有日调用量上限；坐标 CGCS2000，与 WGS-84 差在厘米级，
  门店 / 围栏 / 收货地址直接叠画不偏。两层：`base`（矢量底图 vec_w）+ `label`（注记 cva_w）。
  key 用**浏览器端**类型、域名白名单填站点域名，代理取瓦片时把站点地址带作 Referer —— 请求都由 Keel 发出，
  浏览器与 App 不接触 key。服务端类型的 key 只开放 Web 服务接口，取瓦片回 403「权限类型错误」；
  不带 Referer 从服务端连打两百来次，浏览器端 key 被禁用过一次（2026-09-29）。
  天地图的两台 WAF 节点里有一台对合法的瓦片请求固定回 418，代理遇到 418 换一台重连（最多 5 次）。
- **OpenStreetMap**（`KEEL_MAP_TILES=osm`）：开发与演示用（**演示站 2026-09-30 起用它**，见下）。国内细节偏少、
  没有审图号，官方瓦片服务的使用政策不许商用 App 大流量调用 —— **商业化部署前换回有审图号的服务商**。
  国内服务器直连 tile.openstreetmap.org 不通（域名解析被污染），要配 `KEEL_TILE_PROXY` 走代理。
- **演示站为什么从天地图换走（2026-09-30）**：天地图的华为云 WAF 对服务端代理取瓦片非常敏感 —— 两台节点里一台
  固定 418，重试放大请求之后另一台也对本机 IP 回 418，整站地图全灰，而且没有申诉渠道。天地图适合浏览器直接取瓦片
  （浏览器端 key + 域名白名单）的用法；服务端代理这条路要么换服务商，要么和天地图谈白名单。
- **高德瓦片不用**：不走它的 SDK、不带 key 直接取瓦片没有授权；而且是 GCJ-02，要在客户端纠偏。
- **缓存与限流**：服务端进程内 LRU（64 MB、7 天，只缓存成功的），响应带 `Cache-Control: public, max-age=604800`；
  每 IP 每秒 60 张、瞬时 300 张；另有一道不分 IP 的**总闸**，全站每秒最多向服务商取 20 张、瞬时 400 张
  （只数缓存没命中的），超过回 503 —— 很多个 IP 一起刷也打不爆 key。瞬时额度要够「从全国一路放大到街道」
  （每级两层七八十张）：最初给的瞬时 40 张让放大时一半瓦片被拦、地图留空白（2026-09-29）。
- **没配**：`/geo/map` 报 `enabled: false`，`/geo/tiles` 回 501；买家端不显示「地图选点」
  （小程序照样用微信自带的 `wx.chooseLocation`，不需要底图），后台退回手填坐标。

## 三处接入

| 位置 | 谁来做 | 用法 |
|---|---|---|
| 后台门店地址（`web/admin` 的 LocationPicker） | 本会话 | 地图上方加搜索框：输入提示 → 选中后落点并回填省市区与详细地址 |
| 买家端首页地址 | Flutter 会话 | 定位 → `geo/reverse` 显示「送至 XX 路 XX 号」；点击 → 选已有收货地址或搜索 → 用选中的坐标重新 `stores/resolve` |
| 买家端填收货地址 | Flutter 会话 | 「搜索地点」→ `geo/suggest`；小程序里优先 `wx.chooseLocation`（返回 GCJ-02，客户端转 WGS-84 或交给代理转） |
