# 手册：上新整理

**目的**：商家把商品清单导进来之后（尤其是第一次开店），把能修的问题整理成提案让人一键批准，
修不了的列清楚交给人。商家要的结果是「店能见人」：标题干净、有副标题、都在对的类目里。

## 看哪些工具

- `catalog_issues`（计算）：逐件商品体检，只列有问题的商品。每条问题有 `code` 和 `detail`（依据）；
  `categories` 是可以挪进去的叶子类目（id 与「一级 > 二级」名字路径）；
  `summary` 是各问题码的件数。默认看草稿与上架的商品。
- `list_products` / `get_product`：要看某件商品的详情（规格、价格、描述）时用。
- `list_my_proposals`（查重）：同一件商品已有待处理的 `product_copy` 提案就跳过。
- `propose_product_copy`（提案）：一条提案里可以同时改 `title`、`subtitle`、`category_id`。
- `post_brief`：修不了的问题写进简报。

## 能修的：提 `propose_product_copy`

| 问题码 | 怎么修 |
|---|---|
| `title_noise` | 去掉装饰符号和营销词（【特价】、★、包邮、爆款……），留下「品牌 + 品名 + 关键规格」。**不要编造卖点** |
| `title_too_long` | 压到 30 字以内，规格和数量留下，形容词去掉 |
| `no_subtitle` | 写一句 10–20 字的副标题，只用商品本身已有的信息（标题、描述、规格、类目），不写「最好」「第一」这类词 |
| `forbidden_words` | 换掉命中的词。改完的文案执行时还会再过一遍违禁词检查 |
| `uncategorized` | 在现有类目里挑最合适的叶子类目，给 `category_id`。看不出该放哪就不挪，写进简报 |

同一件商品的几个问题合成**一条**提案。一次巡店最多提 **20 条**，`summary` 里问题多的码优先，
剩下的写进简报，下次接着整理。

## 修不了的：写进简报，交给人

- `no_image`：要商家拍图或给图，AI 不编图；
- `price_outlier`：价格可能多打或少打了一个 0，**AI 不改价**，把 detail 原样列出请人核对；
- `duplicate_title`：可能是同一件商品录了两遍。合并会影响订单历史，只列出来，请人决定；
- `zero_stock`：没有库存的商品上架了也卖不了，请人补库存或下架。

## 证据怎么写

`evidence` 写出调用参数和这件商品的问题原文，例如：

> catalog_issues（默认参数）：商品 #172「【特价】★赣南脐橙 包邮 2.5kg」——
> title_noise：标题里有装饰符号或营销词：【 】 ★ 特价 包邮；no_subtitle：没有副标题；
> uncategorized：还在「未分类」下。
> 建议标题「赣南脐橙 2.5kg」、副标题「当季鲜果，果园直发」、挪到「生鲜 > 水果」（类目 #31）。

## 简报里写什么

- 整理前 `summary` 的各码件数，以及这次提了多少条提案、各修哪几类；
- 修不了的问题逐条列出（商品 id、标题、detail），按「价格异常 → 疑似重复 → 无库存 → 缺图」的顺序，
  前面的会直接造成错单或资损。
