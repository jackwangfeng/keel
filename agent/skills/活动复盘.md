# 手册：活动复盘

**目的**：活动 / 券结束了不代表完事——量出来到底有没有用，写进简报；效果不好又能看出明确改进空间的，
提一条新的调整（不是改旧的，旧活动 / 券已经结束了）。

## 看哪些工具

- `promotion_review`（`promotion_id` 或 `coupon_template_id` 二选一）。
- `list_my_proposals`（查重）。
- `post_brief`（复盘一定要写进简报）；必要时 `propose_coupon` / `propose_flash_price`（新一轮调整）。

## 判断规则

挑最近结束的活动 / 券复盘（比如 3 天内结束的）：

- 活动：看 `current`（活动窗口）vs `previous`（紧邻的前一个等长窗口）的 `sales_cents`、`order_count`、
  `aov_cents`，以及参与 SKU 的 `units_sold`；
- 券：看 `claimed_count`、`used_count`、`use_rate`（核销率）、`sales_cents`（带来的已支付销售额）；

效果判断（用于决定「要不要提调整」，不是唯一标准，别机械套用）：

- 活动期间销售额 / 单量比前一等长窗口明显下降，或参与 SKU 几乎没多卖 → 效果不好，看是不是折扣力度不够、
  时间太短、参与 SKU 选得不对；
- 券核销率很低（比如低于 10%）→ 门槛可能设高了，或者没放进领券中心；
- 效果好 → 简报里写清楚，不用额外提案，除非店长想复制到别的门店 / 商品（那也是新一轮，走一样的判断）。

## 什么时候提案 vs 只写简报

- 复盘本身**永远先写进简报**，不管好坏；
- 只有在能看出**具体、可执行的改进方向**（比如「折扣率提到更低」「门槛降低」「换一批参与 SKU」）且这名
  AI 员工是全店范围时，才额外提一条新的 `flash_price` / `coupon`（当作全新一轮，不是修改上一条）；
- 看不出明确改进方向、或者已经试过一轮效果还是不好 → 只写简报，交给店长判断要不要换思路；
- 同一组 SKU / 同名券已有待处理提案 → 跳过。

## 证据怎么写

复盘部分（进简报）：写清楚 `promotion_review` 的调用参数（`promotion_id` 或 `coupon_template_id`）、
`window` / `previous_window`、`current` 与 `previous` 的具体数字对比，例如：

> promotion_review（promotion_id=17）：限时折扣「9 月清仓周」窗口 09-21～09-27，销售额 ¥12,400（前一等长
> 窗口 ¥9,800，+27%）、单量 86（前 61，+41%）、客单 ¥144（前 ¥161，-11%）；参与 3 个 SKU 共卖出 52 件。

如果接着提新一轮调整，`propose_flash_price` / `propose_coupon` 的 `evidence` 要同时引用这份复盘数字，
说明新提案是照着复盘结果调整的，比如「上一轮 9 折核销率只有 6%，这次门槛从满 200 降到满 100」。

## 上限

- 沿用各自工具的上限（`flash_price`：≤20 SKU、折扣率 500–999‰、≤14 天；`coupon`：面额 / 封顶 ≤100 元、
  发行量 ≤10000、每人限领 1–5、有效期 1–90 天）；
- 新一轮提案需要全店范围的 AI 员工；
- 复盘写简报没有上限，但别堆流水账——只写窗口内结束的、值得说的那几个。
